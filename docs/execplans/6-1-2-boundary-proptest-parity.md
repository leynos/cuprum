## Purpose / big picture

Demonstrate that the optional Rust consumer produces the same captured text as
Python across generated byte sequences, including malformed UTF-8 and inputs
around one mebibyte (1 MiB = 1,048,576 bytes). Rust `proptest` must drive the
actual compiled PyO3 boundary, which exposes Rust functions to Python, with
shrinking enabled: a failure is reduced to a smaller reproducible input.
Preserve the boundary's exception classes, operating-system error codes,
validation order, and descriptor ownership.

The observable result is a mandatory extension test command that reports
executed parity properties and rejects a missing extension. This work supplies
the correctness evidence for later capture-only dispatch. It does not activate
`rust_consume_stream`, claim a speedup, or discharge phase 6's separate 20%
wall-time gate. A passing property suite establishes evidence within its stated
generated domain; it is not an exhaustive proof over all possible inputs.

## Tolerances (exception triggers)

Stop implementation, record the proposed deviation, and request approval if a
production fix, public interface change, dependency addition, interpreter
embedding, or dispatcher change is needed. A discovered parity defect must
first have a named failing regression and an impact assessment; it must not be
accepted as a second permissible output.

The subprocess integration is a feasibility milestone. If it cannot run on the
existing Linux and Windows extension lanes without changing linker policy or
introducing another CI job, stop and present alternatives. Do not quietly
replace real-boundary proptest with engine-only tests. Escalate if the added
warm test execution exceeds five minutes per platform, excluding compilation
and compiler admission waits; retain coverage while investigating cost. There
is no elapsed-time limit on planning or implementation work itself.

The Windows consume-support stop was superseded by the user's explicit
2026-11-03 direction to add Windows native consume support and retain
cross-platform parity. Keep Python's public consume signature and production
dispatch unchanged. Do not infer synchronous I/O from an arbitrary Win32
handle. The Windows consume path must establish a binary CRT-descriptor
boundary for the duration of the call; if that cannot preserve the stated
ownership and error contracts, stop and report the exact incompatibility.

## Risks

- **High impact, low likelihood, repaired 2026-11-15: a write-only CRT
  descriptor could reach `_read` and abort the interpreter.** Raised by the
  hosted assessment and confirmed against the source. `convert_crt_fd` rejects
  only a negative or out-of-`i32` descriptor, and `os.dup` succeeds for an open
  descriptor regardless of its access mode. Microsoft's
  [`_read` contract][ms-read] says the invalid parameter handler is invoked
  when "the file isn't open for reading", and the parameter-validation page
  states the default handler terminates the process.

  The decisive premise — that a valid-range but unusable descriptor fast-fails
  rather than returning `-1` — was settled from the `_read` page itself, which
  documents both rejections and states the continuation return for each: `-1`
  with `EBADF` for a bad or unreadable descriptor, `-1` with `EINVAL` for
  `buffer_size > INT_MAX`. Continuation is permitted only when a handler is
  installed. The Tolerances section reserves production changes for approval,
  so the repair was recorded here first; it is now implemented because it
  preserves the branch's own stated error contract rather than changing it, and
  because the alternative is an exported entry point that terminates the host
  process.

  The repair installs a thread-local invalid-parameter handler around the
  `_read` call, restored on drop, so the CRT takes its documented continuation
  path and the existing `errno` mapping reports `OSError`. `read_crt_once` also
  enforces the `INT_MAX` bound before the call, since exceeding it is a second
  invalid-parameter condition. Two Windows tests in
  `cuprum/unittests/test_rust_errno_windows.py` pass a closed and a write-only
  descriptor from a child process — the regression is the child dying, which an
  in-process assertion could not observe — and two native tests in
  `rust/cuprum-native-io/src/windows_crt.rs` exercise the same shapes directly.
  Likelihood stays low because no production dispatch reaches
  `rust_consume_stream` and every in-repository caller passes a readable
  descriptor.

- **Residual, latent, repaired 2026-11-15: three review findings that could
  not fire on any committed input.** Each was fixed because the guard itself
  was wrong, not because a current case failed. Recorded separately from the
  defect above so the distinction between "observed" and "reasoned" stays
  legible.

  The streamed-witness guard in `tests/helpers/consume_boundary_oracle.py`
  tested length and tail only. `capture_from_producer` can rebuild exactly one
  shape — a repeated `cuprum-boundary/` prefix followed by the tail — so a
  payload of the right length and tail with any other prefix would have
  selected the subprocess witness and failed inside the producer with a
  misleading "named boundary pattern" `ValueError`. No committed named case has
  that shape and `large_payload_strategy` generates a random 1–128-byte pattern
  that cannot equal the prefix, so it never fired. The guard now asks the
  producer's own precondition through a new `is_streamable_payload` predicate
  rather than duplicating its rule, and a four-case parametrized test pins each
  discriminating dimension.

  The ty typing-contract tests redirected only project and ancestor discovery.
  `--config-file` does not bypass user-level configuration, which ty still
  loads and merges, so a contributor whose own `ty.toml` relaxed
  `invalid-argument-type` could have silenced the diagnostic the tests exist to
  require. Verified empirically with ty 0.0.74 in a scratch directory before
  writing the fix, including that ty prefers `XDG_CONFIG_HOME` over `HOME` when
  both are set. `_ty_environment` now redirects both roots and the regression
  asserts that redirection directly, so the test fails if the guard stops doing
  it.

  Two Windows docstrings claimed more than the boundary establishes.
  `_validate_windows_consume_reader` checks range only; whether a descriptor is
  open, readable, and synchronous is not observable from an `int`, and the
  native boundary is what reports those. The docstrings, the design note, and
  the verification table now say so.

- High impact, medium likelihood: a pre-filled pipe blocks on a large input.
  Use temporary files for generated native consumption and a concurrent
  producer only for a small number of real-pipe integration scenarios.
- High impact, medium likelihood: the wrong interpreter or an absent extension
  produces false success. Resolve the project virtual environment explicitly,
  verify its native module path, and make absence fatal in the dedicated gate.
- High impact, low likelihood: a child hangs during input, import, or native
  I/O. Start its watchdog at spawn, include stdin transfer in its deadline,
  drain diagnostics, and kill and reap only that child on timeout.
- Medium impact, medium likelihood: random generation misses a UTF-8 category.
  Combine generated domains with mandatory named witnesses for every category.
- Medium impact, medium likelihood: seed replay changes after strategy edits.
  Version seeds with their source, preserve minimized named regressions, and
  verify replay before changing the generator.
- Medium impact, uncertain status: existing Makefile and CI comments still
  describe a descriptor close race associated with issue #124 and keep the
  extension suite selective. Issue #124 is closed by PR #160, which unified the
  splice loop and fixed `drain_reader` EINTR handling. M1 must verify whether
  the documented race still reproduces before treating it as a current blocker;
  a closed issue alone does not establish that every related failure mode is
  gone. Keep using the repository-defined ordinary and extension test targets
  and report their results accurately.

## Surprises & discoveries

- **A test module can be invisible to every local gate and still be wrong.**
  `tests/helpers/test_consume_boundary_oracle.py` is collected by
  `EXTENSION_TEST_TARGETS` and by the coverage lane, but by neither `make test`
  (whose `PYTEST_TARGETS` never names `tests/helpers/`) nor any guarded local
  run without the extension. The two local routes that do touch it always had
  the extension present, so the missing skip guard was unreachable locally and
  reachable in CI. The lesson is that "green locally" for a module in that
  position proves nothing about its behaviour without the extension; the
  decisive check is to hide the `.so` and run the module directly.

- **A conflict-free rebase is a claim, not a result.** The second rebase
  reapplied 28 commits over 82 changed upstream files with no conflict at all,
  which is easy to read as "nothing to check". A stat line would not have
  settled it: stat totals are name-plus-count pairs, so two different edits can
  produce identical numbers. What settles it is stripped-patch identity —
  compare `base_old..head_old` against `base_new..head_new` with `index` blobs
  and `@@` offsets removed. Only then is it safe to treat the rebase as a
  faithful reapplication and spend the bundle on the new base. The corollary
  matters more than the check: a rebase that *does* conflict gets read closely,
  so the silent clean one is the case where fidelity must be demonstrated.

- **A check that is not required is still worth reading.**
  `CodeScene Code Health Review` is not one of the twelve required contexts in
  the `main-required-checks` ruleset, so its red status never blocked the
  merge. It was reporting a real defect in a file this branch introduced,
  though, and the repair cost one local refactor. The distinction that mattered
  was between a gate that decides whether the branch may land and a finding
  that says something true about the code; conflating them would have meant
  either treating a non-blocking result as fatal or ignoring a genuine defect
  because the branch protection did not enforce it. The local
  `cs review <file>` reproduces the hosted score, so the fix was verified
  before pushing rather than discovered from a second red run.

- **A stale language-server snapshot looks exactly like a broken edit.** After
  the `BoundaryCase` refactor the editor reported
  `E0061: expected 1 argument, found 2` at six call sites, which is precisely
  the error a half-finished signature change produces. It was not real. The
  cited lines were the *pre-edit* numbering — the current line 235 is a
  `payload.replace` statement, not a call — and the target had already compiled
  clean after the rewrite. The rule that follows is that a diagnostic about a
  file rewritten outside the editor is a hypothesis until the compiler has been
  asked directly; compiling the target, not reading the squiggles, is what
  settles it.

A green Linux extension job did not prove the parity target's route was safe.
`extension-tests` installs the dev-fast prerequisites before it calls
`make test-extension`, so the dev-fast prerequisite on `test-boundary-parity`
resolved there and the route looked correct. The `modern-stable` job calls
`make modern-stable`, which reaches the same extension target without those
prerequisites, and it failed with
`install rustc-codegen-cranelift for nightly-2026-08-23 before using dev-fast`
after the Rust and Python suites had already passed 278 tests. A prerequisite
that a shared target inherits is only exercised by the jobs that actually reach
it, so a passing one-consumer job says nothing about the other consumers.

The repository's contracts already encoded the correct answer: the
modern-stable lane is required to stay free of dev-fast, and `setup-dev-fast`
is pinned to exactly two `ci.yml` uses. Those assertions ruled out the easy
fixes (adding the action to a third job, or dropping the contract) and pointed
at the dependency itself as the defect, which is why the parity target now uses
the plain Cargo route rather than widening either job.

Post-rebase `make test` passed 4,245 tests and skipped 96, but ten typing
contract cases timed out. A bounded experiment showed that an unrelated
`/tmp/pyproject.toml` made the checker scan thousands of temporary files.
Explicit fixture scope reduced the same check to one file and 1.118 seconds; an
explicit empty configuration also prevents inherited rule suppression. See
[the diagnosis](../debugging/debugging-plan-2026-10-24-typing-project-discovery.md).
This test-harness repair is separate from the unapproved parity
implementation. The subsequent full run passed the typing suite, then exposed a
stale Ruff diagnostic assertion. The import-order fixture now uses the
repository's configuration explicitly and checks its named `unsorted-imports`
diagnostic.

A later full run exposed a separate lifecycle-fixture startup race: its 50 ms
pipeline deadline could expire before the held native worker started. A 100 ms
dispatch delay reproduced the failure. The fixture now waits for worker
readiness before arming the same short deadline, retaining the real timeout and
deferred-cleanup paths. See the
[startup diagnosis](../debugging/debugging-plan-2026-10-25-native-pump-startup.md).

passed every focused Python run, `make lint-windows`, and `make check-fmt`, yet

A Windows CRT unit test that probes an invalid descriptor kills the whole test
binary, so the suite reports a crash rather than a failed assertion. The first
CI run on the pushed head failed `Native contracts (windows-2022)` with
`exit code: 0xc0000409, STATUS_STACK_BUFFER_OVERRUN`. The archived
`native-boundaries-Windows` log shows `running 11 tests` followed by seven
`... ok` lines and then the failure; neither `windows_crt` test name appears.
The order is the diagnosis: `maps_invalid_crt_descriptor_to_windows_error`
sorts before `reads_binary_pipe_bytes_to_eof`, so it ran first and died before
the harness could print its name. That code is not a stack overrun here; it is
`__fastfail`, the CRT's deliberate fast-fail path. Microsoft documents that
`_read` invokes the invalid parameter handler when `fd` is invalid, that the
default handler is `_invoke_watson`, and that `_invoke_watson` calls
`__fastfail` with `FAST_FAIL_INVALID_ARG` and terminates the process; the
`-1`/`EBADF` return only happens if a handler is installed and *allows*
execution to continue. Release builds install none, so
`maps_invalid_crt_descriptor_to_windows_error` could never have observed its
asserted error on Windows. The defect was invisible to every focused run, and to
`cargo test` on Linux generally, because the test is `#[cfg(windows)]` and
this branch is developed on Linux.

The same defect appeared twice more in the Python lane, which is why one root
cause produced three red jobs. `test_consume_maps_an_invalid_crt_descriptor`
called the native entry point directly with `1_000_000` and asserted
`WinError 6`; it aborted the interpreter mid-session, which is the stray
`test_rust_errno_windows.py::test_consume_maps_an_invalid_crt_descriptor` line
that `make test-extension` printed after its own `Error 127`.
`test_buffer_validation_precedes_descriptor_conversion[consume]` was skipped on
Windows, and that skip was the tell: the wrapper duplicated the CRT descriptor
*before* native buffer validation, so the parameter row could not run there.
The wrapper now validates the buffer and then the CRT descriptor before
`os.dup`, which restores the order the native entry point documents on every
platform and removes the reason for the skip.

A second consequence is that the documented `-1`/`EBADF` branch is unreachable
for any descriptor fault a test can synthesize against `_read` directly.
Microsoft's documentation for `_read` makes the invalid parameter handler, not
an error return, the response when `fd` is not valid, is not open for reading,
or is locked, so an out-of-range, closed, or unreadable descriptor all take the
same terminating path. The mapping in `crt_read_error` therefore cannot be
witnessed end to end. It is now a pure function, `classify_crt_read_error`,
taking the three observed error values and returning the native code; the
CRT-observing wrapper only gathers them. That keeps the assertion meaningful
without requiring the process to survive parameter validation, and it separates
the fallible read from the decision about what its failure means. The Python
test was rewritten to assert the rejection the wrapper can actually guarantee,
and a new case pins the buffer-before-descriptor order with both arguments
invalid. A closed-but-in-range descriptor still reaches `OSError` on the Python
path because `os.dup` rejects it before the CRT is called, which is why the
existing `test_propagates_io_errors` was green throughout.

  consume prepares the CRT descriptor before native entry, while the direct
  native function validates `buffer_size` before its descriptor conversion. The

  direct-native order tests continue to cover that platform's native contract.
  **Superseded 2026-11-09; see the entry below.** This states the order as it
  was before that repair, and is retained as the record of what was approved at
  the time rather than silently rewritten.
- (2026-11-09) Reverse the Windows consume wrapper to buffer-first, then
  descriptor validation, then `os.dup`. The earlier reader-first layer looked
  safer because it kept an unusable descriptor away from `_read`, but it
  surfaced `os.dup`'s `OSError` for an argument the entry point documents as
  `ValueError`, and it put the wrapper out of step with the native function's

  buffer-first for the Windows consume wrapper, matching the native entry point.
  `_validate_windows_consume_reader` rejects an out-of-range value before
  `os.dup`, but it checks the descriptor's range only: an open descriptor that
  is closed, write-only, or otherwise unusable for reading still passes it and
  reaches `_read`. The native boundary installs a continuing invalid-parameter
  handler so that case returns an error instead of terminating the process; see
  the 2026-11-15 decision below and the repair recorded in Risks.
- (2026-11-15) Repair the two invalid-parameter paths at the native CRT
  boundary rather than documenting them as caller obligations. `read_crt_once`
  installs a thread-local invalid-parameter handler for the duration of the

  CRT rejects returns `-1`/`EBADF` and is mapped to `OSError` instead of
  invoking the default handler's `__fastfail`. It also rejects a buffer larger
  than `INT_MAX` before the call. Records the Tolerances approval point: this
  was recorded in Risks before implementation, and is in scope because it
  preserves the entry point's documented error contract instead of changing it.
- (2026-10-13) Propose a test-only subprocess bridge. Rust owns generation,
  shrinking, and persistence; a project-Python child calls the installed
  extension and the actual Python consumer. This avoids both a copied oracle

  classification and Python exception-object assertions at their current layers.
- (2026-10-13) Use separate small and large domains. Small buffers expose split
  code points cheaply; practical buffers cover large transfers without a
  million single-byte reads on every generated case.
- (2026-10-13) Preserve ordinary-suite and extension-suite separation. The
  new gate belongs to the existing extension workflow, not production routing
  or a new scheduled CI service.
- (2026-10-24) Record #90, #124, and #127 as closed with merged implementation
  PRs. Closure supplies context, not completion evidence for roadmap 6.1.2.
  Keep the extension lane selective as currently configured, and verify the
  remaining #124 race claim before changing test-environment requirements.
- (2026-11-05) Place a platform contract in the module that already owns that
  platform's boundary, not merely beside the operation it exercises. The
  Windows CRT text-mode case moved from `test_rust_consume_stream.py` to
  `test_rust_errno_windows.py`. Both modules describe the same consume
  operation, but only the latter is Windows-scoped, so the move colocated the
  Windows-only assertions and kept the cross-platform module under the
  repository's 400-line cap without deleting a case. The general rule: when a
  file approaches the cap, prefer relocating a case to the module that owns its
  contract over compressing the surrounding code.
- (2026-11-05) Keep the wheel-manifest snapshot change minimal. Adding the one
  new shipped module in sorted position is preferred to regenerating the
  snapshot, because regeneration rewrites unrelated rows and hides which entry
  actually changed. The snapshot test's own redaction of generator and version
  is what makes the hand edit safe.

- (2026-11-15) Establish background mode by duplication rather than by caller
  obligation. The unsafe `borrow_crt_reader` was the wrong shape: it accepted a
  bare current-operation integer and pushed binary mode plus liveness onto
  whoever called it, and a direct caller of `rust_consume_stream` had no way to
  discharge either. `duplicate_crt_reader` is safe because it *creates* the
  state it needs — a duplicate, in binary mode, owned by the returned value —
  so the borrow that `cuprum-streams` sees can only come from an owner that
  keeps it valid. This is the crate's existing rule ("safe operations accept
  resources the process already owns, and raw integers only become resources
  here") applied to the CRT rather than to file descriptors. The Python
  wrapper's own duplicate is retained deliberately: it protects the caller's
  translation mode before the GIL is released, which the native duplicate
  inside the detached call cannot do because by then the mode decision is
  already made.
- (2026-11-15) Prove the abort hazard with a child process, and prove the child
  is not vacuous. A process abort cannot be observed from inside the process
  that aborts, so the case must run in a child; but libtest exits zero when a
  filter selects nothing, which means a renamed case would silently turn the
  proof into a no-op. Selecting the child with `--exact`/`--ignored` avoids the
  environment channel that `rust/clippy.toml` disallows, and asserting on the
  child's own `... ok` result line is what distinguishes "the case passed" from
  "the case never ran". The same reasoning applies to the Make target's
  existing 30-test count guard.

## Context and orientation

Begin with `docs/contents.md`, `docs/repository-layout.md`, and `AGENTS.md`.
`cuprum/_streams.py::_consume_stream` is the Python behavioural reference. It
accepts an `asyncio.StreamReader` and `_StreamConfig`. Capture-only
configuration sets `capture_output=True`, `echo_output=False`,
`encoding="utf-8"`, and `errors="replace"`, with an `io.StringIO` sink and no
line callback.

`cuprum/_streams_rs.py` adapts Python descriptors to native handles, including
Windows preparation. `rust/cuprum-rust/src/stream_pyfunctions.rs` exposes
`rust_consume_stream` and `rust_pump_stream`, with a default buffer of 65536.
`rust/cuprum-rust/src/errors.rs` maps semantic errors to Python exceptions.
`cuprum-streams` owns stream mechanics and incremental decoding; native
resource handling belongs to `cuprum-native-io`. A descriptor is an
operating-system reference to an open file or pipe. Duplicating one can share
its file offset; independent comparisons must not consume the same exhausted
position.

Existing support lives in `cuprum/unittests/_rust_stream_test_support.py` and
`tests/helpers/stream_pipes.py`. Existing Rust error tests are
`rust/cuprum-rust/src/stream_error_tests.rs` and `stream_error_behaviour.rs`;

`test_rust_stream_native_order.py` under `cuprum/unittests/`, plus

## Proposed test design and interfaces

Add `rust/cuprum-rust/tests/consume_boundary_parity.rs`, a Cargo integration
suite that does not import PyO3 or the native library's symbols. Reuse the
existing `proptest` dependency. Place supporting Rust code under
`rust/cuprum-rust/tests/support/` only when the file-size or cohesion rule
requires it. Mark extension-dependent tests explicitly ignored in ordinary
Cargo runs, with a reason naming the mandatory boundary command.

Add a test helper at `tests/helpers/consume_boundary_oracle.py`, reusing
ordinary support functions where appropriate; never call pytest fixtures
directly from the standalone child. Keep it test-only and importable for
pytest. Its typed callable accepts payload bytes and a positive buffer size. A
small Cyclopts entry point receives that size as an argument and reads raw
payload bytes from stdin; no JSON protocol or additional serialization library
is needed. Resolve the virtual environment's interpreter using the Makefile's
environment conventions, including Windows's `Scripts/python.exe`. The child
must report `sys.executable` and the native module file path; `make develop`
from the candidate source establishes build provenance. Verify that the module
is the expected checkout or virtual-environment artefact, not an unrelated
installation, then call through `cuprum._streams_rs`.

For each case, consume three independent temporary files through the native
wrapper: omit `buffer_size`, pass 65536, and pass the generated size. Each file
contains the same bytes and starts at offset zero. Close every file reliably
and verify the borrowed reader remains valid after consumption. Feed another
copy into `asyncio.StreamReader`, signal end of input, and call the actual
`_consume_stream` using `asyncio.run`. Assert all outputs equal each other and
`payload.decode("utf-8", errors="replace")`. Additionally invoke
`cuprum._rust_backend_native.rust_consume_stream` directly with omitted and
explicit 65536 buffers, using separate resources and the existing platform
handle preparation. The Python wrapper always forwards its default explicitly,
so wrapper-only comparisons cannot test the native signature default. Compare
both direct results against both Python oracles. The Python reference must
never call the Rust consumer. Test that separation with an injected failing
native call. It supplies the future dispatch oracle without activating dispatch.

Exit zero only after every assertion. A mismatch exits non-zero with a bounded
reason identifying the failed comparison, payload length, buffer, and first
mismatch; do not print a megabyte of data. Rust converts it into
`TestCaseError::fail`, preserving shrinking. Missing dependencies, import
failure, malformed arguments, and child termination must fail, never skip or
return success.

The parent starts a 30-second per-child watchdog before spawn. Input writing
and stdout/stderr draining must run without blocking watchdog progress; retain
at most 16 KiB of diagnostics while continuing to drain both output streams.
Close stdin to signal end of input. On timeout, kill and reap the owned child
and join its I/O workers. Every shrink attempt starts fresh. Unit-test success,
mismatch, early exit, large input, a child that never reads stdin, a child
flooding diagnostics, and a child hanging after input; no clock-sensitive speed
assertions belong inside the parity property.

Add `make test-boundary-parity`, using the existing prescribed Cargo route and
project interpreter. It must select only this test target and explicitly run
its ignored cases; zero selected tests is a failure of acceptance. Invoke this
target sequentially from `make test-extension` after its Python checks, so the
existing Linux and Windows extension CI jobs inherit it. Add or extend Makefile
contract tests proving this routing and that ordinary `make test` keeps its
extension-free contract. Do not add a second CI execution of the same suite.
Check toolchain availability in both jobs during M1. Windows uses its existing
stable 1.87 route; only Linux uses the prescribed dev-fast route. Preserve the
existing Windows job timeout and report added duration. The existing
`make boundary-test` checks native integration and verifier contracts; this new
target specifically owns cross-language consume parity.

## Verification plan

V1 preserves decoding parity. Generate arbitrary byte vectors of length 0–4096
and construct valid ASCII and 2-, 3-, and 4-byte Unicode scalar runs, including
mixtures with invalid bytes. Exclude surrogate code points when constructing
valid Unicode; include their malformed encodings in invalid-byte cases. Use
constructive strategies rather than rejection-heavy filters. Execute 256 small
cases with buffers 1–8, 9–65535, 65536, and 65537. The mandatory witnesses
include empty, NUL, ASCII, each multibyte width, lone continuations, overlong
encodings, surrogate encodings, bytes above U+10FFFF, and truncated sequences
at end of input. Place multibyte sequences across read boundaries with
deterministic prefix padding, including splits at 1–4 and 65535–65537 bytes.
E1/E2 pass only when the actual Python consumer and decoder both agree with all
wrapper and direct-native results. A temporary wrong-result mutation must fail
and produce a reduced input; remove it before committing.

V2 preserves large-transfer and default-buffer equivalence. Execute 16 large
cases with lengths 1,048,572–1,048,580 and practical buffers 4096, 65535,
65536, and 65537. Generate a shrinkable short pattern, repetition count, and
tail so the strategy does not store a million independent choices. Include all
nine mandatory byte lengths from 1,048,572 through 1,048,580, valid multibyte
tails, and malformed tails. Also retain an arbitrary-byte small domain:
patterned large inputs do not imply coverage of every large byte vector. V2
uses the same oracle and E3, with a truncation mutation as its negative control.

V3 preserves exception mapping and ownership for both entry points. Extend
existing parameterized pytest and Hypothesis tests only where a matrix audit
finds gaps: invalid buffer values within i64 map to `ValueError`; values beyond
i64 retain extraction `OverflowError`; unsupported argument types retain
`TypeError`; native descriptor range failures retain their documented
`ValueError`; real read/write failures retain `OSError` class or subclass,
`errno`, and Windows `winerror` where applicable. Pin repository-owned messages
exactly, but compare OS-derived messages against a same-platform reference, not
English literals. Cover competing invalid arguments to establish native
buffer-before-descriptor validation separately from Windows wrapper handle
preparation. Audit each entry point separately: the pump wrapper validates its
buffer before reader preparation, and Windows consume validates its buffer
before validating or duplicating its CRT descriptor. Correct stale
property-test commentary rather than imposing a uniform order. Reuse existing
owned-resource fixtures; never invent arbitrary positive descriptor numbers
that could alias unrelated open resources. Consume borrows its reader; assert
its continued usability after success and each reachable error, not just
equality of a descriptor number. Pump writer adoption and cleanup must follow
the existing contract on success and failure. E4 includes the existing `rstest`
and `rstest-bdd` classification suite plus real Python exception assertions. A
removed error assertion or broad `except` is not an acceptable green result.

V4 preserves reproducibility and harness integrity. Configure case counts and
non-zero shrink budgets explicitly in code; use 1024 shrink iterations for
small cases and 128 for large cases initially, plus a 120-second shrink-time
budget per failing property. Timeouts are failures, not discarded examples.
Record any runtime budget adjustment with evidence rather than reducing counts
to conceal a failure. Use an explicit source-associated regression path such as
`rust/cuprum-rust/tests/consume_boundary_parity.proptest-regressions`. Commit
real failure seeds and promote minimized counterexamples to named tests. Also
commit a separate curated replay seed corpus under
`rust/cuprum-rust/tests/fixtures/consume_boundary_seeds.txt`, labelled as
coverage seeds rather than historical defects. Generate and replay those seeds
using the installed proptest version's supported seed API; never hand-invent
persistence syntax. Preserve the developers' guide policy that regression files
contain only genuine unmodified-code failures. If no defect is found, report
curated replay evidence explicitly instead of claiming a historical regression;
this is the proposed interpretation of the roadmap seed requirement for
approval. Disable persistence during deliberate mutation checks. Prove replay
works by running the named replay check with fresh-case generation disabled,
then run the normal property budget. E5 must show a replayed case and a
rejected negative control; an empty file does not satisfy acceptance.

The external assumptions are Python's documented UTF-8 replacement semantics,
PyO3's integer extraction and exception interfaces, temporary-file seek/read
semantics, and proptest's generation, shrinking, and seed replay contracts.
Exercise their composition through the real installed extension rather than
attempting to prove third-party internals. No new production lemma, axiom, or
contractual business algorithm is introduced. Verus or Kani would not prove
this interpreter and operating-system boundary; no formal proof is claimed. If
a production pure-kernel fix becomes necessary, reassess its obligations and
substantive proof opportunity before seeking deviation approval.

Keep existing focused `insta` decoding snapshots. Generated equality and error
fields require semantic assertions, not large snapshots. Add `syrupy` or
`insta` snapshots only if implementation introduces a stable multivariant
human-facing diagnostic format worth preserving; redact paths and OS wording
and pair any snapshot with semantic assertions. No output-format change is
currently proposed.

## Milestones and plateaus

### M1: prove the bridge is real and bounded

Implement the minimal helper, one named parity witness, Rust process support,
and required Makefile integration together. Add pytest helper unit tests and
`rstest` process tests. Show the required command fails when the native module
cannot load and that an injected mismatch reaches Rust as a shrinkable failure.
Run a sleeping-child fixture to prove timeout cleanup includes input transfer.
Confirm Linux and Windows route selection, native module provenance, and that
ordinary Rust tests do not link an interpreter. This plateau advances R1/R6;
its acceptance is E1 and the routing contract tests. Generated-domain and
behavioural coverage remain for M2/M3. Commit only after the applicable gates.

### M2: cover generated domains, errors, and replay

Implement V1–V4, add named `rstest` and pytest witnesses, and extend the
existing Hypothesis boundary tests for genuinely missing cases. Reuse fixtures
rather than adding another error taxonomy. Record a red negative control before
the green harness, and add a real regression before any approved bug fix. Never
change correct production behaviour merely to manufacture a red test: this is a
coverage addition, so injected test defects are the appropriate sensitivity
evidence when production already satisfies the property.

Persist curated replay seeds and any genuine failures, run replay alone, then
run the configured fresh budgets. This plateau discharges R2–R5 through E2–E5.
Record counts, exercised partitions, minimized failures, and warm runtime in
this plan. Keep all properties and child failure paths active after refactoring.

### M3: Windows consume support, behavioural acceptance, and documentation

Use a Windows CRT descriptor for native consume. Python must duplicate the
validated descriptor, set the duplicate to binary mode, pass that duplicate to
the native consume call, and close it in `finally`; this keeps the caller's
descriptor open and avoids mutating its text mode. The native reader must use
the synchronous CRT descriptor API and must not treat an arbitrary Win32 handle
as synchronously readable. Keep the existing handle capability checks for the
pump path. The Python public signature and production dispatch remain
unchanged. See Microsoft's documentation for
[`_read`](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/read?view=msvc-170),
[`_dup`](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/dup-dup2?view=msvc-170),
and
[`_setmode`](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/setmode?view=msvc-170).

Extend `tests/features/rust_streams.feature` and its actual bound pytest-bdd
module, or add a focused sibling feature and module to `EXTENSION_TEST_TARGETS`
if existing structure cannot accommodate it. Confirm the feature path before
editing. The acceptance scenarios must include these statements:

```gherkin
Feature: Capture-only stream boundary parity
  Scenario: A large malformed stream preserves Python replacement decoding
    Given a payload of 1048577 bytes ending with an incomplete UTF-8 sequence
    When the native and Python consumers capture the complete payload
    Then both captures equal Python UTF-8 replacement decoding
    And omitted and explicit default buffers produce the same capture
    And the caller's reader descriptor remains open

  Scenario: Invalid buffers retain the native exception contract
    Given valid stream descriptors and a buffer size of zero
    When each native stream entry point is called
    Then a ValueError reports the buffer validation failure
```

Keep or extend the existing Rust `stream_errors.feature` with bound
`rstest-bdd` scenarios for classification witnesses missing from its current
coverage. Existing passing scenarios count as evidence; avoid duplicating them.
Use real pipe/subprocess integration for one large capture with a concurrent
producer, complete output assertions, EOF, and deterministic cleanup. This is
the end-to-end evidence for the helper/native boundary; it must call the native
consumer directly and preserve tests that forbid production dispatch.

Record the subprocess test boundary and its reuse limits in
`docs/cuprum-design.md`; record commands, budgets, replay, and failure
diagnosis in `docs/developers-guide.md`. If implementation introduces a
substantive architecture decision beyond this test-only bridge, add an ADR
following the style guide and link it from the design document and
`docs/contents.md`. Update `docs/repository-layout.md` if new test directories
need explanation. Review `docs/users-guide.md`: retain its
implemented-but-not-integrated statement; change it only for an approved
user-visible correction, documenting that reason here. Complete the full
sequential gates and reconcile every conformance link. Only then mark 6.1.2
`[x]` in `docs/roadmap.md` and this plan COMPLETE. The planning PR must not
mark the feature done.

At every plateau, check its assigned requirements, retained architecture,
external assumptions, public interfaces, dependencies, resource boundaries, and
evidence links. No compatibility shim is needed for these test-only interfaces.
Recovery is to revert only the owning atomic commit or repair its fixtures,
then rerun affected gates; later milestones must not depend on an unvalidated
partial bridge.

## Idempotence and recovery

Each property case creates and closes its own resources. No test may close a
reused descriptor number after another resource has taken ownership. Temporary
files and children must be cleaned up even after assertion failures. Replay and
repeated gates must not depend on a previous interpreter's state.

Keep regression files through clean builds. Discard only labelled mutation
artefacts after preserving their diagnostic evidence in logs. Do not erase a
real failing seed to obtain a passing run. When source paths or generators
change, update persistence paths and prove replay still exercises the intended
case. Preserve prior commits as rollback points and keep the living plan
aligned with the current validated plateau.

## Research and review notes

Upstream documentation was consulted through Firecrawl during planning:

- [Proptest failure persistence][proptest-persistence] explains persisted seeds
  and recommends committing regression files. The implementation must verify
  the precise API and format against the installed 1.11.0 release.
- [PyO3 0.29.0 building and distribution][pyo3-building] documents extension
  build and interpreter-linking distinctions. Existing repository test comments
  independently confirm why a child interpreter is preferable here.

The community review covers architecture, alternatives, performance,
correctness, reliability, and maintainability. Pandalump and Wafflecat endorsed
the subprocess bridge while requiring independent file offsets, mandatory
coverage classes, and a fatal missing extension. Telefono identified
native-default masking and different wrapper validation orders; direct native
comparisons and per-entry-point error checks now address them. Dinolump
required curated seeds to remain separate from genuine regressions. Buzzy Bee
and Doggylump required deadlines covering input transfer, draining after
diagnostic limits, bounded shrinking, and existing platform-specific gate
routing. Those requirements are included above.

The trade-off is extra process-launch cost for real proptest-driven boundary
evidence without changing PyO3 linkage. M1 measures that cost and validates
platform feasibility before wider coverage. The user approved this plan on
2026-10-25; implementation may proceed within its stated tolerances.
