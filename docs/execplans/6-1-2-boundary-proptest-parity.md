## Purpose / big picture

Demonstrate that the optional Rust consumer produces the same captured text as
Python across generated byte sequences, including malformed UTF-8 and inputs
around one mebibyte (1 MiB = 1,048,576 bytes). Rust `proptest` must drive the
actual compiled PyO3 boundary, which exposes Rust functions to Python, with
shrinking enabled: a failure is reduced to a smaller reproducible input.
Preserve the boundary's exception classes, operating-system error codes,
validation order, and descriptor ownership.

The observable result is a mandatory extension test command that reports
executed parity properties and rejects a missing extension. This work supplies
the correctness evidence for later capture-only dispatch. It does not activate
`rust_consume_stream`, claim a speedup, or discharge phase 6's separate 20%
wall-time gate. A passing property suite establishes evidence within its stated
generated domain; it is not an exhaustive proof over all possible inputs.

## Risks

- High impact, medium likelihood: a pre-filled pipe blocks on a large input.
  Use temporary files for generated native consumption and a concurrent
  producer only for a small number of real-pipe integration scenarios.
- High impact, medium likelihood: the wrong interpreter or an absent extension
  produces false success. Resolve the project virtual environment explicitly,
  verify its native module path, and make absence fatal in the dedicated gate.
- High impact, low likelihood: a child hangs during input, import, or native
  I/O. Start its watchdog at spawn, include stdin transfer in its deadline,
  drain diagnostics, and kill and reap only that child on timeout.
- Medium impact, medium likelihood: random generation misses a UTF-8 category.
  Combine generated domains with mandatory named witnesses for every category.
- Medium impact, medium likelihood: seed replay changes after strategy edits.
  Version seeds with their source, preserve minimized named regressions, and
  verify replay before changing the generator.
- High impact, known limitation: the complete Python suite with an installed
  extension can abort through the separate descriptor race in issue #124.
  Follow the existing split between ordinary and extension-required suites;
  never describe an aborted or skipped run as passing.

## Surprises & discoveries

Roadmap 6.1.1 is already complete. `RustStreamError` lives in
`rust/cuprum-rust/src/lib.rs`; `run_stream_operation` in
`rust/cuprum-rust/src/stream_pyfunctions.rs` validates buffers, converts the

The existing crate tests deliberately avoid interpreter linkage.

`cuprum/unittests/test_rust_consume_stream.py` already uses Hypothesis and
Python replacement decoding. Its nominal 4096-byte cap exceeds its current
chunk generator's actual maximum, so merely raising that constant would not
exercise large inputs. Default-buffer properties in

bytes. Rust properties in `rust/cuprum-streams/src/consume_snapshot_tests.rs`

alone satisfies the requested Rust-generated cross-language boundary property.

used direct source reads and exchanged evidence through context packs

## Proposed test design and interfaces

Add `rust/cuprum-rust/tests/consume_boundary_parity.rs`, a Cargo integration
suite that does not import PyO3 or the native library's symbols. Reuse the
existing `proptest` dependency. Place supporting Rust code under
`rust/cuprum-rust/tests/support/` only when the file-size or cohesion rule
requires it. Mark extension-dependent tests explicitly ignored in ordinary
Cargo runs, with a reason naming the mandatory boundary command.

Add a test helper at `tests/helpers/consume_boundary_oracle.py`, reusing
ordinary support functions where appropriate; never call pytest fixtures
directly from the standalone child. Keep it test-only and importable for
pytest. Its typed callable accepts payload bytes and a positive buffer size. A
small Cyclopts entry point receives that size as an argument and reads raw
payload bytes from stdin; no JSON protocol or additional serialization library
is needed. Resolve the virtual environment's interpreter using the Makefile's
environment conventions, including Windows's `Scripts/python.exe`. The child
must report `sys.executable` and the native module file path; `make develop`
from the candidate source establishes build provenance. Verify that the module
is the expected checkout or virtual-environment artefact, not an unrelated
installation, then call through `cuprum._streams_rs`.

For each case, consume three independent temporary files through the native
wrapper: omit `buffer_size`, pass 65536, and pass the generated size. Each file
contains the same bytes and starts at offset zero. Close every file reliably
and verify the borrowed reader remains valid after consumption. Feed another
copy into `asyncio.StreamReader`, signal end of input, and call the actual
`_consume_stream` using `asyncio.run`. Assert all outputs equal each other and
`payload.decode("utf-8", errors="replace")`. Additionally invoke
`cuprum._rust_backend_native.rust_consume_stream` directly with omitted and
explicit 65536 buffers, using separate resources and the existing platform
handle preparation. The Python wrapper always forwards its default explicitly,
so wrapper-only comparisons cannot test the native signature default. Compare
both direct results against both Python oracles. The Python reference must
never call the Rust consumer. Test that separation with an injected failing
native call. It supplies the future dispatch oracle without activating dispatch.

Exit zero only after every assertion. A mismatch exits non-zero with a bounded
reason identifying the failed comparison, payload length, buffer, and first
mismatch; do not print a megabyte of data. Rust converts it into
`TestCaseError::fail`, preserving shrinking. Missing dependencies, import
failure, malformed arguments, and child termination must fail, never skip or
return success.

The parent starts a 30-second per-child watchdog before spawn. Input writing
and stdout/stderr draining must run without blocking watchdog progress; retain
at most 16 KiB of diagnostics while continuing to drain both output streams.
Close stdin to signal end of input. On timeout, kill and reap the owned child
and join its I/O workers. Every shrink attempt starts fresh. Unit-test success,
mismatch, early exit, large input, a child that never reads stdin, a child
flooding diagnostics, and a child hanging after input; no clock-sensitive speed
assertions belong inside the parity property.

Add `make test-boundary-parity`, using the existing prescribed Cargo route and
project interpreter. It must select only this test target and explicitly run
its ignored cases; zero selected tests is a failure of acceptance. Invoke this
target sequentially from `make test-extension` after its Python checks, so the
existing Linux and Windows extension CI jobs inherit it. Add or extend Makefile
contract tests proving this routing and that ordinary `make test` keeps its
extension-free contract. Do not add a second CI execution of the same suite.
Check toolchain availability in both jobs during M1. Windows uses its existing
stable 1.85 route; only Linux uses the prescribed dev-fast route. Preserve the
existing Windows job timeout and report added duration. The existing
`make boundary-test` checks native integration and verifier contracts; this new
target specifically owns cross-language consume parity.

## Verification plan

V1 preserves decoding parity. Generate arbitrary byte vectors of length 0–4096
and construct valid ASCII and 2-, 3-, and 4-byte Unicode scalar runs, including
mixtures with invalid bytes. Exclude surrogate code points when constructing
valid Unicode; include their malformed encodings in invalid-byte cases. Use
constructive strategies rather than rejection-heavy filters. Execute 256 small
cases with buffers 1–8, 9–65535, 65536, and 65537. The mandatory witnesses
include empty, NUL, ASCII, each multibyte width, lone continuations, overlong
encodings, surrogate encodings, bytes above U+10FFFF, and truncated sequences
at end of input. Place multibyte sequences across read boundaries with
deterministic prefix padding, including splits at 1–4 and 65535–65537 bytes.
E1/E2 pass only when the actual Python consumer and decoder both agree with all
wrapper and direct-native results. A temporary wrong-result mutation must fail
and produce a reduced input; remove it before committing.

V2 preserves large-transfer and default-buffer equivalence. Execute 16 large
cases with lengths 1,048,572–1,048,580 and practical buffers 4096, 65535,
65536, and 65537. Generate a shrinkable short pattern, repetition count, and
tail so the strategy does not store a million independent choices. Include all
nine mandatory byte lengths from 1,048,572 through 1,048,580, valid multibyte
tails, and malformed tails. Also retain an arbitrary-byte small domain:
patterned large inputs do not imply coverage of every large byte vector. V2
uses the same oracle and E3, with a truncation mutation as its negative control.

V3 preserves exception mapping and ownership for both entry points. Extend
existing parameterized pytest and Hypothesis tests only where a matrix audit
finds gaps: invalid buffer values within i64 map to `ValueError`; values beyond
i64 retain extraction `OverflowError`; unsupported argument types retain
`TypeError`; native descriptor range failures retain their documented
`ValueError`; real read/write failures retain `OSError` class or subclass,
`errno`, and Windows `winerror` where applicable. Pin repository-owned messages
exactly, but compare OS-derived messages against a same-platform reference, not
English literals. Cover competing invalid arguments to establish native
buffer-before-descriptor validation separately from Windows wrapper handle
preparation. Audit each entry point separately: the pump wrapper validates its
buffer before reader preparation, while consume prepares its reader first.
Correct stale property-test commentary rather than imposing a uniform order.
Reuse existing owned-resource fixtures; never invent arbitrary positive
descriptor numbers that could alias unrelated open resources. Consume borrows
its reader; assert its continued usability after success and each reachable
error, not just equality of a descriptor number. Pump writer adoption and
cleanup must follow the existing contract on success and failure. E4 includes
the existing `rstest` and `rstest-bdd` classification suite plus real Python
exception assertions. A removed error assertion or broad `except` is not an
acceptable green result.

V4 preserves reproducibility and harness integrity. Configure case counts and
non-zero shrink budgets explicitly in code; use 1024 shrink iterations for
small cases and 128 for large cases initially, plus a 120-second shrink-time
budget per failing property. Timeouts are failures, not discarded examples.
Record any runtime budget adjustment with evidence rather than reducing counts
to conceal a failure. Use an explicit source-associated regression path such as
`rust/cuprum-rust/tests/consume_boundary_parity.proptest-regressions`. Commit
real failure seeds and promote minimized counterexamples to named tests. Also
commit a separate curated replay seed corpus under
`rust/cuprum-rust/tests/fixtures/consume_boundary_seeds.txt`, labelled as
coverage seeds rather than historical defects. Generate and replay those seeds
using the installed proptest version's supported seed API; never hand-invent
persistence syntax. Preserve the developers' guide policy that regression files
contain only genuine unmodified-code failures. If no defect is found, report
curated replay evidence explicitly instead of claiming a historical regression;
this is the proposed interpretation of the roadmap seed requirement for
approval. Disable persistence during deliberate mutation checks. Prove replay
works by running the named replay check with fresh-case generation disabled,
then run the normal property budget. E5 must show a replayed case and a
rejected negative control; an empty file does not satisfy acceptance.

The external assumptions are Python's documented UTF-8 replacement semantics,
PyO3's integer extraction and exception interfaces, temporary-file seek/read
semantics, and proptest's generation, shrinking, and seed replay contracts.
Exercise their composition through the real installed extension rather than
attempting to prove third-party internals. No new production lemma, axiom, or
contractual business algorithm is introduced. Verus or Kani would not prove
this interpreter and operating-system boundary; no formal proof is claimed. If
a production pure-kernel fix becomes necessary, reassess its obligations and
substantive proof opportunity before seeking deviation approval.

Keep existing focused `insta` decoding snapshots. Generated equality and error
fields require semantic assertions, not large snapshots. Add `syrupy` or
`insta` snapshots only if implementation introduces a stable multivariant
human-facing diagnostic format worth preserving; redact paths and OS wording
and pair any snapshot with semantic assertions. No output-format change is
currently proposed.

## Idempotence and recovery

Each property case creates and closes its own resources. No test may close a
reused descriptor number after another resource has taken ownership. Temporary
files and children must be cleaned up even after assertion failures. Replay and
repeated gates must not depend on a previous interpreter's state.

Keep regression files through clean builds. Discard only labelled mutation
artefacts after preserving their diagnostic evidence in logs. Do not erase a
real failing seed to obtain a passing run. When source paths or generators
change, update persistence paths and prove replay still exercises the intended
case. Preserve prior commits as rollback points and keep the living plan
aligned with the current validated plateau.

correctness, reliability, and maintainability. Pandalump and Wafflecat endorsed
the subprocess bridge while requiring independent file offsets, mandatory
coverage classes, and a fatal missing extension. Telefono identified
native-default masking and different wrapper validation orders; direct native
comparisons and per-entry-point error checks now address them. Dinolump
required curated seeds to remain separate from genuine regressions. Buzzy Bee
and Doggylump required deadlines covering input transfer, draining after
diagnostic limits, bounded shrinking, and existing platform-specific gate
routing. Those requirements are included above.

The trade-off is extra process-launch cost for real proptest-driven boundary
evidence without changing PyO3 linkage. M1 measures that cost and validates
platform feasibility before wider coverage. Approval remains the user's
decision.
