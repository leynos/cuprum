### H6: Asyncio loses or cannot deliver the child-exit notification

**Claim**: During the intermittent stall, the short-lived child has already
exited but the event loop's process transport or child watcher does not deliver
completion to `process.wait()`.

**Plausibility**: High — combining the wait and stream tasks in one `gather`
does not change the failure, bare subprocesses usually complete, and the
pytest-timeout stack shows an idle selector rather than active application
work.

**Prediction**: At the stall, the child is a zombie or already absent while
the process waiter remains pending; task and transport state identify the
missing completion edge.

#### H6 Falsification Plan

| Step | Action | Expected Negative Result |
| --- | --- | --- |
| 1 | Run a bounded diagnostic that dumps asyncio tasks, process PID, return code, transport state, and OS child state before cancellation | Child remains normally running or blocked on application-owned I/O |
| 2 | Trace SIGCHLD/wait syscalls for one short reproduction | The parent receives and handles the exit notification normally |

**Tooling**: Focused Python diagnostic, `ps`, `strace`, asyncio task stacks.

**Confidence on falsification**: High when task, transport, and OS process

### H6 outcome

H6 survived. During a captured stall, the child was absent from `/proc` and
already reaped, `process.returncode` and the transport return code were both
zero, the transport was finished, and both pipe transports were closed.
Nevertheless, `Process.wait()` remained on a pending future.

Guard all process-exit waits through a shared lifecycle helper that races the
normal asyncio waiter against a low-frequency watcher of the public
`process.returncode` property. Prefer the normal waiter whenever it completes,
and always cancel and drain the losing task. Both single-command execution and
pipeline waiting use the helper; termination also uses it when no existing
pipeline wait task is available. Deterministic process doubles publish return
code zero while leaving `wait()` pending, and a public-boundary regression
repeats short captured commands to cover the original intermittent failure.
